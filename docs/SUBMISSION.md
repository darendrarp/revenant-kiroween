## Text description (paste into Devpost)

> **The problem:** 38% of the web pages that existed in 2013 are already gone.
> Link rot eats citations, bookmarks, and personal history a little every day —
> and when a link dies, most people just hit a dead end.
>
> **REVENANT resurrects dead links.** Paste any URL: REVENANT checks whether it
> is alive, and if it is dead, digs up its last good snapshot from the Internet
> Archive's Wayback Machine and brings the page back — with a tombstone showing
> its born/died years and cause of death, a year-by-year life timeline, an
> embedded snapshot viewer, and a clean Reader view. A Graveyard Audit scans
> any live page for dead outbound links; Bulk Check triages up to 25 URLs at
> once; and The Graveyard keeps every soul you revive in local history on your
> device only.
>
> **What makes it different:** it is honest by design — if the archive has no
> snapshot, REVENANT says so instead of inventing one. It is free forever: no
> account, no API key, no fee. And it is built spec-first with Kiro: EARS
> requirements, design, and a task list in `.kiro/specs/` written before any
> code, steering docs, event-driven hooks, and property-based tests (1,000+
> generated cases) that caught two real bugs during the build.
>
> **Try it:** `geocities.com`, `posterous.com`, `formspring.me` — three famous
> ghosts, all verified dead with snapshots waiting.

## Kiro usage (paste into the Devpost write-up field)

> REVENANT was built spec-first, the Kiro way. Before any code, I wrote a full
> spec in `.kiro/specs/revenant/`: eight requirements in EARS notation
> (`WHEN … THE SYSTEM SHALL …`), a design doc with architecture and a decision
> log, and a 15-task implementation plan with each task citing its
> requirements. The build followed the task list in order, and the two real
> design changes during the build (parallelizing the three resurrect lookups;
> replacing the CDX timeline with availability-API anchor sampling after CDX
> proved unreliable) are recorded in the design decision log.
>
> Steering docs (`.kiro/steering/product.md`, `tech.md`, `structure.md`) plus
> a root `AGENTS.md` carry the product context, the zero-dependency constraint,
> the 10-second serverless budget, and the safety rules (validate before you
> fetch; the reader endpoint only fetches `web.archive.org`). Agent hooks
> (`.kiro/hooks/*.json`, schema v1) automate the workflows I followed: run the
> test suite when API/test files save, syntax-check saved frontend JS, and
> prompt a spec update after each task. An MCP config (`.kiro/settings/mcp.json`)
> wires the `fetch` server for Kiro sessions. Kiro CLI 3.5.0 was installed and
> verified on the build machine.
>
> Honest limitation: no authenticated Kiro agent session ran during this build
> — Kiro sign-in needs an interactive browser/device-flow step the headless
> build VM cannot complete (the device-flow menu renders, but no device code
> is printed after selecting a method). No code was generated by a Kiro agent
> session; the `.kiro/` artifacts are genuine spec-first artifacts authored to
> Kiro's documented formats, and the repo is ready for a Kiro session to
> continue. Full details: `docs/KIRO_USAGE.md` in the repo.
>
> Property-based testing deserves a mention: the property-style suite
> (`tests/property.test.js`, seeded PRNG, 1,000+ generated cases) caught two
> real bugs a unit test would likely have missed — a link-extraction regex
> that treated a stray quote as an href, and an IPv6-bracket gap in the SSRF
> guard. Both are fixed and covered by unit tests. `npm test`: 18/18 green.

## Testing instructions (for judges — no login needed)

1. Open https://revenant-kiroween.vercel.app
2. Click a demo ghost (GeoCities / Posterous / Formspring) — each resurrects a
   real dead site with its tombstone, timeline, snapshot viewer, and Reader
   view.
3. Or paste any URL. Try `example.com` (alive — shows its snapshot anyway) and
   a dead link of your own.
4. Graveyard Audit: paste `https://news.ycombinator.com` and watch 60 links
   get checked in batches.
5. Bulk Check: paste a few URLs, one per line (max 25).
6. The Graveyard section keeps your revivals on your device only.
7. Run it locally: `git clone` the repo, `npm test`, `npm run dev`
   (http://localhost:3000) — no keys, no login, zero dependencies.
