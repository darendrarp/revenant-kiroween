# REVENANT — Resurrect the Dead Web

> **Kiroween 2026 · Resurrection category.** Paste a dead link. REVENANT checks
> whether it is alive, digs up its last snapshot from the Internet Archive's
> Wayback Machine, and brings the page back — tombstone, life story, and all.

🔗 **Live app:** https://revenant-kiroween.vercel.app
📺 **Demo video:** _(link added when the video is uploaded — see
[`docs/DEMO_VIDEO_SCRIPT.md`](docs/DEMO_VIDEO_SCRIPT.md))_

38% of the web pages that existed in 2013 are already gone. Link rot eats
citations, bookmarks, and personal history a little every day. REVENANT is the
shovel: one paste tells you whether a URL is alive, and if it is dead, resurrects
its archived version with its life story.

## Features

- **Resurrect a link** — liveness check + closest Wayback snapshot + a
  "tombstone" (born/died years, cause of death) + a year-by-year life timeline.
  View the snapshot in an embedded viewer or as a clean Reader view.
  Shareable deep links (`#r=<url>`) resurrect on load.
- **Graveyard audit** — paste any page and get every outbound link checked, with
  a dead/alive summary and one-click resurrection for each dead link.
- **Bulk check** — up to 25 URLs at once, for bibliographies and bookmark
  exports.
- **The Graveyard** — every soul you revive is kept in local history on your
  device only. Nothing leaves your browser.
- **Honest by design** — if the archive has no snapshot, or cannot be reached,
  REVENANT says so. It never invents archive data.

No account. No API key. No fee. The only external service is the Internet
Archive's public, keyless Wayback Machine API.

## Tech

- **Frontend:** static HTML/CSS/vanilla JS in `public/` — no framework, no build
  step, no bundler.
- **Backend:** Vercel Serverless Functions (Node 20+, CommonJS) in `api/` —
  **zero npm dependencies**.
- **Tests:** Node's built-in test runner, including property-style tests with
  generated inputs (`tests/property.test.js`).
- **Hosting:** Vercel. Static `public/` + `api/` functions.

```
Browser ──▶ Vercel Functions (resurrect / check / audit / extract)
                 │  (public hosts only, short timeouts, partial results)
                 ▼
         Internet Archive Wayback Machine  +  target sites (liveness)
```

See [`.kiro/specs/revenant/design.md`](.kiro/specs/revenant/design.md) for the
full architecture, including why the timeline samples the availability API
instead of CDX, and how every function stays inside Vercel's 10s Hobby limit.

## API

| Endpoint | Method | Purpose |
| --- | --- | --- |
| `/api/resurrect?url=` | GET | Liveness + closest snapshot + timeline + tombstone |
| `/api/check` | POST `{urls: [...]}` | Bulk liveness (1–12 URLs), snapshots for dead ones |
| `/api/audit?url=` | GET | Extract a page's outbound links (≤60) |
| `/api/extract?url=` | GET | Reader view of a `web.archive.org` snapshot |

Safety: user URLs are validated before any fetch (HTTP(S) only, no localhost,
no private/link-local IPs). `/api/extract` only fetches `web.archive.org`, so it
cannot be abused as an open proxy.

## Local development

```bash
npm test        # 19 tests (unit + property-style), no dependencies
npm run dev     # serves http://localhost:3000 — static frontend + real API handlers
```

No Vercel login needed for local dev: `scripts/dev-server.mjs` routes `/api/*`
to the same handlers Vercel runs.

## How Kiro was used

REVENANT was built **spec-first, the Kiro way**: requirements (EARS), design,
and a task list were written in `.kiro/specs/revenant/` before any code, with
steering docs (`.kiro/steering/`), event-driven hooks (`.kiro/hooks/`), and an
MCP config (`.kiro/settings/mcp.json`) committed alongside the code. Kiro CLI
3.5.0 was installed and verified on the build machine.

One honest limitation: **no authenticated Kiro agent session ran during this
build** — Kiro sign-in needs an interactive browser/device-flow step that the
headless build VM cannot complete. No code in this repo was generated by a Kiro
agent session. The `.kiro/` artifacts are real, spec-first, and ready for a Kiro
session to continue: open the repo in Kiro IDE (or `kiro-cli`), and the spec,
steering, and hooks activate as documented. Full details, including exactly what
was attempted and how to continue in Kiro:
[`docs/KIRO_USAGE.md`](docs/KIRO_USAGE.md).
